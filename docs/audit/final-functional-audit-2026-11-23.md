## Подтверждённые правила приложения

- Android: minSdk 23, targetSdk/compileSdk 35, Java/Kotlin toolchain 17.
- Фиды: `docs/data.json` и `docs/uefa-data.json`; сетевое обновление выполняется в фоне, используется ETag и локальный кеш.
- Восемь активных рынков: 1X, X2, ОЗ ДА, ТБ 2.5, ИТБ 0.5/1.5 хозяев и гостей.
- TOP: вероятность не ниже 60%, EV не ниже 5%, EDGE не ниже 5 п.п., точный коэффициент MelBet не ниже 1.50; один лучший допустимый рынок на матч, ранжирование по full-Kelly. Kelly используется для ранжирования, а не как автоматическая доля ставки.
- TOP-статистика опирается на архив реально выбранных TOP-сигналов и совместимые ранее сохранённые ручные TOP-записи. ALL учитывает все завершённые прогнозы. Для TOP применяются диапазоны уверенности от 60%, для ALL — от 50%.
- Ставки ведутся как локальная бумажная история. Автоматическое создание новых ставок и размещение реальных ордеров не выполняются; фоновая задача обновляет результаты уже сохранённых записей.
- Android и сборщик фидов считают котировку свежей до 12 часов при активном prematch-рынке и корректной временной метке.

## Исправления в PR #284

1. Добавлена обработка system bars и display cutout для Android 15 / targetSdk 35.
2. Фоновое уведомление теперь выбирает тот же один TOP-сигнал, что и экран; вторичный рынок не вызывает уведомление, если экран его не показывает.
3. Выбор legacy UEFA paper-сигнала согласован с foreground fallback.
4. TOP-сводка всегда показывает все восемь активных рынков. Для нулевой выборки выводятся нулевые счётчики и прочерки, а не NaN/деление на ноль.
5. Большие JSON-фиды вынесены из SharedPreferences в приватные файлы. SharedPreferences оставлены для ETag и временных меток; старый кеш мигрирует при первом чтении; неизменившийся merged JSON не перезаписывается на каждом минутном опросе.
6. Foreground и background используют общий `FeedMerger`: объединяются не только UCL/UEL/UECL матчи, но и их завершённые evaluation-записи. Это исправляет неполный офлайн-кеш статистики.
7. Backend Android-parity audit теперь проверяет активность и свежесть MelBet-котировки и фильтрует P/EV/EDGE до ранжирования, как Android.
8. Добавлены JVM/Python regression tests для ранжирования, кеша, объединения фидов, свежести котировок и выбора кандидатов.

## Открытые блокеры перед заявлением «готово к подписи»

1. **Проверка на устройстве не выполнена.** Нет подтверждённого прогона на Android 15 и на минимальном API 23; нет UI instrumentation tests, измерений frame time, холодного старта, расхода памяти и фоновой работы. Поэтому гарантировать «вообще не лагает» по одному CI нельзя.
2. **Спецификация стратегии расходится сама с собой.** Markdown называет BetBoom и допускает более широкий набор рынков, JSON и runtime используют MelBet и восемь активных рынков. Лимиты просадки/дневной и матчевой экспозиции в Markdown и JSON различаются. В Android-коде не обнаружено автоматического применения таких стопов/лимитов; просадка рассчитывается для отчёта. Финансовые правила не менялись без отдельного согласования.
3. **Разная свежесть UEFA paper-выборки.** Android/feed builders допускают до 12 часов, а `evaluate_uefa_paper_signals.py` ограничивает возраст котировки пятью минутами. Это может менять историческую выборку и parity. Не менялось без подтверждения, какой порог является утверждённым.
4. **Исторический TOP-архив локальный.** Прогнозы, которые не были сохранены в архив TOP на устройстве, нельзя достоверно восстановить задним числом из текущего фида.

## Вердикт

Основные backend-проверки и восьмитурнирный аудит проходят; ключевые расхождения Android/background/backend выявлены и исправлены в отдельном PR.
